# MARCH 제품 기획 · v0.2 파일럿

## 문제와 사용자

릴스와 링크를 저장해도 시간이 지나면 무엇을 보려고 저장했는지 기억하기 어렵다. 특히 레시피의 계량, 영상 속 방문 정보, 학습 자료의 핵심 절차는 원문을 다시 열어 찾아야 한다. MARCH는 평소 링크를 모아두는 사용자가 **저장할 때는 링크만 보내고, 다시 찾을 때는 정리된 정보와 근거를 바로 확인**할 수 있게 한다.

## P0 범위

| 단계 | 사용자 경험 | 판정 기준 |
| --- | --- | --- |
| 연결 | 초대형 웹 계정으로 로그인. Instagram을 쓰려면 웹 연결 코드 → DM 전송 → 원래 웹 세션에서 승인 | 연결 대상과 웹 계정의 소유권을 모두 확인 |
| 저장 | 웹에 URL 입력 또는 봇에 공유. 제목·태그·폴더를 먼저 정할 필요 없음 | 재전달과 중복 URL에도 보관 항목을 한 번만 생성 |
| 원문 확보 | 권한이 확인된 설명문이나 등록된 원문을 사용 | 원문이 없으면 링크를 유지하고 `링크만 저장됨` 표시 |
| 정리 | 한줄 요약, 분류, 태그, 확인된 개체와 원문 근거 제공 | 분량·시간·주소가 원문에 없으면 미확인으로 표시 |
| 재검색 | 키워드·도메인 필터로 찾아 상세 열기. 원문과 개인 메모 확인 | 원문 근거와 사용자가 편집한 값이 구분됨 |

요리 카드에는 확인된 재료·계량·단계를 보여준다. 가령 마늘 `2쪽`은 보존하고, 새우에 계량이 없으면 `분량 미표기`로 표시한다. 콘텐츠가 요리라고 분류돼도 사용자가 촬영 구도를 참고하려고 저장했을 수 있으므로 개인 목적은 기본 `unknown`으로 둔다.

## 로컬 구현과 출시 게이트

- **실행 가능** · FastAPI와 정적 HTML/CSS/JS, SQLite, 독립 Python Worker로 URL을 저장하고 원문이 있으면 정리한다. 검색·편집·삭제까지 연결된다.
- **실계정 시험 대기** · Instagram Webhook, 계정 연결, 권한 있는 소유 계정의 설명문 동기화 코드가 있다. 실제 권한과 일반 사용자 DM 수신을 확인해야 한다.
- **출시 게이트** · 일반 사용자가 평소 저장하는 콘텐츠로 전체 저장 대비 원문 확보율과 유효 정리율을 측정한다. 7일 뒤 다시 찾기 과제에서 요약·태그의 실제 효용을 확인한다. 실험에서 실패한 입력도 분모에 포함한다.

## 확장 순서

1. **P0** · 자체·협력 계정과 제3자 공개 콘텐츠의 접근 범위 검증, 실제 저장물의 재검색 파일럿.
2. **P1** · 권한 있는 영상으로 텍스트·직접 영상 분석·STT/OCR 경로 비교. YouTube와 블로그 획득 경로, 레시피·장소 카드, 의미 검색과 출처 기반 Chat 검토.
3. **P2** · 브라우저 확장과 모바일 공유로 입력 단계를 줄인다. [초대형 공유 컬렉션](SHARING.md)은 개인 카드 선택 공유와 여행 후보 공동 보관을 위한 확장 아이디어로 둔다.
4. **P3** · 실제 재사용이 확인된 영역에서 장보기, 여행 일정, 학습 노트와 내보내기를 검토한다.
