# 공유 컬렉션 구상

**제안 단계.** 제주 여행 일행이 각자 저장한 맛집 릴스와 장소 링크 중 필요한 것만 한곳에 모으는 흐름부터 검증한다.

## 첫 사용 흐름

1. `제주 여행` 컬렉션을 만들고 함께 가는 사람을 초대한다.
2. 개인 카드에서 `공유 컬렉션에 담기`를 고른다. 보내기 전에 상대에게 보일 제목·원본 링크·요약을 미리 본다.
3. 편집 권한이 있는 멤버는 링크를 직접 추가하거나, 공유 메모와 `후보` / `확정` 상태를 수정한다.
4. 더 이상 공유할 필요가 없는 카드는 컬렉션에서 제거한다. 해당 멤버의 개인 보관함에서는 계속 찾을 수 있다.

한 번 링크만 건네고 싶다면 원본 URL 복사로 충분하다. MARCH의 정리 카드 한 장까지 보여주고 싶다면 초기에 한 장만 담은 공유 컬렉션으로 처리할 수 있다. 로그인 없이 열 수 있는 만료·회수 가능한 읽기 링크는 수요가 확인되면 별도로 검토한다.

## 권한과 데이터

| 역할 | 할 수 있는 일 |
| --- | --- |
| 소유자 | 초대·권한 회수, 컬렉션 편집, 항목 관리 |
| 편집자 | 항목 추가, 자신이 추가한 항목 제거, 공동 메모·상태 편집 |
| 보기 전용 | 컬렉션 읽기와 원본 링크 열기 |

공유 항목은 추가 시점에 확인한 제목·원본 링크·요약의 사본으로 저장한다. 개인 카드의 메모·태그·전체 원문과 연결 계정 정보는 사본에서 제외한다. 개인 카드 수정과 재분석은 공유 사본을 자동으로 바꾸지 않는다. 개인 카드 삭제 화면은 공유 사본이 따로 남는 경우를 안내하고, 공유 사본 회수는 별도 동작으로 제공한다. 원문 삭제·처리 철회 시 공유 사본의 정리와 보존기간은 파일럿 전에 확정한다.

백엔드에서는 컬렉션, 멤버십, 공유 항목을 별도로 관리한다. 목록·상세·쓰기에서 멤버십을 검사하고, 초대 링크는 만료되는 일회용으로 발급한다. 초대를 받은 사용자는 로그인해 수락한다. 멤버십을 회수하면 해당 사용자의 새 요청을 즉시 차단한다. 공유 카드는 컬렉션 권한으로 읽고, 원본 개인 카드의 접근권은 그대로 개인에게 둔다.

## 파일럿에서 볼 것

- 여행 일행이 개인 메모 노출 없이 후보를 담고 다시 찾을 수 있는가.
- 여러 사람이 같은 링크를 담을 때 같은 컬렉션 안에서 카드 한 장으로 관리되는가.
- 초대가 만료되거나 권한이 회수된 뒤 상세 주소로 다시 접근해도 거절되는가.
- 공동 메모와 후보 상태만으로 계획이 충분히 정리되는가. 댓글·투표·일정표는 관찰한 필요에 따라 검토한다.
